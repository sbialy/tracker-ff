# The plugin ABI contract of the release under test (read by fw_engine_mismatch_sim.sh, scenario 0, so by release_gate.sh).
# This is ABI 1.4 (PLUG_ABI_MINOR 4, PLUG_HOST_LEVEL 2): what synth-open/plug/plug_abi.h of this tree has to say, line for line. One line per fact:
#   define NAME VALUE       every PLUG_ #define of the header
#   struct NAME SHA1        sha1 (first 12 hex digits) of the struct body with comments and white space normalised: field order, types and names, so
#                           a moved, retyped, renamed or inserted field (a changed offset) turns the gate RED
#   enum NAME VALUE         every enum member (extension ids, kinds, cpus, error codes, flags)
# Why it is here: ABI 1.4 (the plugin files extension) raised PLUG_HOST_LEVEL 1 -> 2 (host->query answers PLUG_EXT_FILES), appended the optional
# service and view to plug_ext_synth (tail fields, read only when struct_size covers them) and added PLUG_EXT_FILES / PLUG_EXT_STRUM and the
# plug_ext_files / plug_ext_strum / plug_ext_tempo structs. All of it is additive, so the "old against new" checks of the simulator accept it
# (host level and minor may only go up, a struct may only grow at its tail, an enum member may only be added, a min_host up to the host level
# is accepted and one above it is refused) and THIS file is what pins the new contract: an ABI change that nobody meant (a different host level,
# a wrong field offset, a changed enum value) is a RED check "the ABI is the pinned contract".
# An intended ABI change: edit plug_abi.h, regenerate this file with the command below, read the diff, say in the commit why.
#   python3 -I <(sed -n '/^cat >"$WORK\/fwm.py"/,/^PY$/p' fw_engine_mismatch_sim.sh | sed '1d;$d') contract synth-open/plug/plug_abi.h
